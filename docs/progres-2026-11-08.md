# Progres 8 November 2026 — S1: backend enam jenis surat final

Branch `feat/letters-final-types` dari `origin/main` `0605421`. Rancangan: `docs/PROMPTS-SURAT.md` (sesi S1).

## Lingkup

Backend menerima enam jenis surat final (DOMISILI, SKTM, BELUM_MENIKAH, KERAMAIAN, KEHILANGAN, UMUM) dengan data diri dan isian khusus per jenis. SKU dan KTP_KK tetap ada untuk data lama, tetapi pengajuan baru ditolak (422). Nomor surat memakai format desa. Kontrak frontend dan demo mengikuti. Formulir warga (S3), template PDF resmi (S2), dan tampilan panel (S4) **tidak** diubah.

## Keputusan sesi

- **Isian milik jenis lain ditolak** (`prohibited`, 422), tidak diabaikan: tidak ada data yang tersimpan tanpa disadari dan kesalahan klien terlihat. String kosong/null tetap diterima.
- **KERAMAIAN:** agama, status perkawinan, pendidikan, pekerjaan tidak wajib, tetapi bila dikirim tetap divalidasi (sesuai kata "tidak wajib" di rancangan).
- **Rentang keramaian ≤ 7 hari** dihitung termasuk hari mulai dan selesai (10–16 boleh, 10–17 ditolak).
- **`keperluan` tetap wajib untuk semua jenis** (rancangan: dicatat petugas untuk DOMISILI/BELUM_MENIKAH; dicetak untuk SKTM/UMUM; "Maksud" pada KERAMAIAN).
- **Kolom tambahan `isi_keterangan_awal`** (di luar daftar kolom tugas): teks asli warga untuk pembanding yang diminta S4. Tidak pernah berubah.
- **Sunting isi keterangan:** staff/admin; status `SUBMITTED`, `RT_APPROVED`, `RW_APPROVED`, `VERIFIED`, `PROCESSING`, `NEED_REVISION`. Aturan di `ApplicationStatus::canEditContent()`; riwayat `action: STATEMENT_EDITED`, catatan "Isi keterangan disunting"; audit `application.statement_edited` tanpa isi.
- **RT/RW:** bila flag dinyalakan, semua jenis kecuali SKU melalui RT/RW (sebelumnya DOMISILI/SKTM/KTP_KK).
- **Data diri tambahan** (agama, status perkawinan, kewarganegaraan, pendidikan, pekerjaan) hanya untuk peran kantor di detail; Ketua RT/RW tidak menerimanya.
- **Retensi:** `applications:purge` mengosongkan keempat belas kolom baru (tidak diminta tugas, tetapi wajib menurut prinsip retensi).
- **Panel admin:** tiga skema Zod (`application-detail`, `dashboard`, `letter-register`) memakai `serviceCodes` agar data jenis baru tidak membuat panel gagal parse. Tampilan tidak berubah; label jenis baru masih kosong sampai S3/S4.
