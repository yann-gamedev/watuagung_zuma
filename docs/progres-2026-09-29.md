# Catatan perubahan — 29 September 2026

## Keputusan layout

Pengguna menyetujui layout yang dipulihkan ke versi sebelum pembaruan fondasi visual/navbar/footer, mengacu pada commit `b8b1080`. Pemulihan mencakup stylesheet, beranda, hero, navbar/footer, identitas sidebar, dan favicon. Identitas Sprout serta gaya visual lama kembali sebagai konsekuensi rollback yang dipilih pengguna.

Menu BUMDES tetap dipertahankan sebagai tautan langsung ke `/bumdes`, menggantikan dropdown Informasi. Akses berita, agenda, pengumuman, potensi, statistik, dan transparansi tetap tersedia melalui footer.

## BUMDES

Halaman Badan Usaha Milik Desa menggunakan dua kolom pada desktop dan satu kolom pada lebar 768 px ke bawah. Halaman memiliki metadata dan memakai shell publik yang sama. Nama badan usaha, pengurus, unit usaha, alamat, serta kontak resmi tidak dikarang; informasi yang belum tersedia diberi keterangan. Tidak ada fitur transaksi baru.

## Pemeliharaan

- ESLint kini mengecualikan dependensi Composer serta cache/output generasi secara spesifik, tanpa menonaktifkan aturan aplikasi secara luas.
- Panduan integrasi diperbarui dari petunjuk Apps Script usang menjadi kontrak Laravel yang aktif.
- Backend, autentikasi, validasi, payload API, pemisahan simulasi/API, dan perlindungan kode akses tidak diubah.

## Verifikasi dan keterbatasan

Pemeriksaan setelah rollback: `npm run lint`, `npx tsc --noEmit`, dan `npm run build` lulus. Build menghasilkan 33 halaman, termasuk `/bumdes`.

HTTP beranda, formulir SKU, dan admin pernah mengembalikan 200 sebelum rollback terakhir. Pengujian visual/interaksi setelah rollback belum lengkap: layanan browser sebelumnya mengalami 503 lalu kuota 429. Persetujuan layout dari pengguna bukan pengganti pengujian otomatis semua ukuran layar. Tidak ada klaim API end-to-end lulus pada tahap ini.

Build menampilkan peringatan nonfatal mengenai lockfile di luar repository. Tidak ada perubahan konfigurasi terkait peringatan tersebut.

## Tindak lanjut

1. Verifikasi manual lebar 360, 390, 768, dan 1440 px: menu, fokus keyboard, footer, overflow, formulir, dan login admin.
2. Lengkapi data resmi BUMDES dan konten desa setelah diverifikasi.
3. Uji alur API dengan data fiktif pada backend yang tersedia.

Pembaruan ini dipersiapkan untuk commit dan push atas persetujuan pengguna. Tidak ada perintah deployment yang dijalankan; workflow hosting otomatis, bila terpasang, dikelola oleh konfigurasi repository/hosting.
