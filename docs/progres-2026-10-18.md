# Progres 18 Oktober 2026 — M2: status pengambilan dan wewenang per peran

Branch: `feat/status-roles`. Tidak ada dependensi baru (Laravel Boost tidak dipasang sesuai persetujuan pengguna).

## Ringkasan

Alur surat kini berjalan sampai warga mengambil surat:

`SUBMITTED → VERIFIED → PROCESSING → WAITING_APPROVAL → APPROVED → READY_FOR_PICKUP → COMPLETED`, plus `NEED_REVISION` dan `REJECTED`.

Wewenang per peran dijaga di server. Hanya `village_head` yang memutuskan `WAITING_APPROVAL`; admin tidak dapat menyetujui. Alur persetujuan masih **[SEMENTARA]** di PRODUCT.md sampai dikonfirmasi pihak desa.

## Backend

- `backend/app/Domain/ApplicationStatus.php` (baru): enum status + satu-satunya tabel transisi per peran (`rules()`, `isTransition`, `canTransition`, `allowedFor`, `requiresNote`, `PANEL_ROLES`).
- `StaffController`:
  - login dan `/staff/me` menerima `staff`, `village_head`, `admin` (tetap satu ability `applications:manage`);
  - `index` memeriksa peran (403), memvalidasi `status` **atau** `statuses[]` (saling eksklusif) dan `page`, paginasi di server, dan setiap item memuat `allowed_transitions`;
  - `update`: transisi di luar alur → 422 `Transisi status tidak valid.`; transisi sah tetapi bukan wewenang → 403 `Peran Anda tidak berwenang melakukan perubahan status ini.`; catatan wajib untuk `REJECTED`/`NEED_REVISION`; status dibaca ulang dengan `lockForUpdate` di dalam transaksi; `application_events.user_id` diisi; respons memuat `allowed_transitions` baru.
- `routes/console.php`: perintah `php artisan staff:create {username} --role= --name= --email=` dengan prompt kata sandi tersembunyi (minimal 12 karakter, diketik dua kali).
- Tes: `tests/Feature/StatusWorkflowTest.php` (baru) — setiap transisi yang diizinkan per peran (data provider), seluruh kombinasi lain ditolak tanpa efek samping (>200 kasus), staff/admin tidak bisa menyetujui, kepala desa tidak bisa melakukan pekerjaan kantor, transisi melompat/dari status akhir, catatan wajib, audit `user_id`, filter `status`/`statuses[]` + paginasi, validasi, tanpa token, peran salah, ability salah, penurunan peran setelah token terbit, klien usang, login/me kepala desa, dan perintah `staff:create`. `ApplicationsApiTest` dan `StaffSessionTest` disesuaikan.
- Dokumentasi: `backend/README.md` (tabel wewenang, cara membuat akun lokal tiga peran), `docs/integrasi.md` (kontrak `allowed_transitions`, `statuses[]`, menu admin).

## Frontend

- `types/pelayanan.ts`: status baru, `StaffRole` + `village_head`, `StaffApplication`, `StaffApplicationsPage`, `StaffStatusResponse`.
- `components/site.tsx`: label, deskripsi, dan ikon "Siap diambil" dan "Selesai". `app/globals.css`: badge memakai `--leaf`/putih sesuai DESIGN.md.
- `features/pelayanan/status-checker.tsx`: linimasa tujuh tahap; tautan Kontak juga untuk "Siap diambil".
- `services/pelayanan.ts` + `scripts/test-demo.mjs`: contoh demo `REQ-2026-000005` (Siap diambil) dan `REQ-2026-000006` (Selesai); tes bahwa status tersebut tidak bergerak dan tidak mengubah penyimpanan.
- `features/admin/applications-table.tsx`: konstanta `transitions` dihapus; tombol dibentuk dari `allowed_transitions` dengan label Verifikasi, Proses, Ajukan ke Kepala Desa, Setujui, Tandai siap diambil, Tandai sudah diambil, Minta perbaikan, Tolak.
- `components/admin-sidebar.tsx`, `app/admin/[section]/page.tsx`, `features/admin/shell.tsx`, `features/admin/session.tsx`: menu "Persetujuan" (`/admin/persetujuan`, hanya kepala desa, berisi `WAITING_APPROVAL`); "Surat disetujui" menjadi "Siap diambil" (`APPROVED` + `READY_FOR_PICKUP`); label peran "Kepala Desa"; skema profil sesi menerima `village_head`.

# M3: pencarian, detail permohonan, dan audit akses

Branch: `feat/admin-applications`. Tanpa dependensi baru dan tanpa Laravel Boost (disetujui pengguna).

## Keputusan pengguna

- Detail dapat dibuka `staff`, `village_head`, dan `admin`; wewenang perubahan status tetap mengikuti M2.
- Nama pencarian boleh berada di `q` pada URL. NIK, KK, telepon, alamat, catatan, dan token tetap tidak boleh masuk URL.
- Tata letak detail: kolom data + riwayat dan panel aksi kanan di desktop; satu kolom di layar sempit.

## Backend

- `GET /staff/applications`: `q` (literal, maks. 100, nomor/nama), `jenis_surat`, `sort=terbaru|terlama`, urutan stabil. Item daftar hanya `request_id`, `nama`, `jenis_surat`, `status`, `created_at`, `allowed_transitions`; `catatan` dihapus dari daftar.
- `GET /staff/applications/{request_id}`: otorisasi peran dan ability sebelum query/dekripsi; ID salah 422, tidak ada 404; detail lengkap, `allowed_transitions`, dan riwayat; `Cache-Control: private, no-store`.
- Tabel `audit_logs`; setiap detail berhasil mencatat `application.viewed` sebelum respons dikirim. Tidak ada data pribadi, payload, query pencarian, IP, atau user agent.
- `StaffApplicationsTest` baru: semua peran panel, tanpa token, peran/ability salah, validasi, 404, audit, kegagalan audit, pencarian/filter/sort/pagination, wildcard literal, dan daftar tanpa field sensitif.

## Frontend

- `/admin/permohonan`, `/admin/persetujuan`, `/admin/surat` memakai daftar bersama dengan query string. Persetujuan tetap `WAITING_APPROVAL`; Siap diambil tetap `APPROVED`/`READY_FOR_PICKUP`.
- Tabel desktop, kartu ≤ 600px, dan tautan keyboard ke detail.
- `/admin/permohonan/detail/?id=...`: ringkasan, data diri, alamat, usaha SKU, keperluan, NIK/KK tersamar per field, linimasa, aksi server, catatan wajib, dan dialog konfirmasi.
- Kembali ke daftar memakai section dan filter yang telah divalidasi. Panel detail lama dihapus.

## Verifikasi saat commit

- `php artisan test`: 94 tes, 925 asersi, lulus.
- `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm run test:demo`, dan `node scripts/test-admin-filters.mjs`: lulus.
- Database sementara dengan data fiktif disiapkan untuk uji browser. Pada saat push, uji browser 390px/1440px dan tinjauan kode independen belum selesai; hasilnya dilaporkan terpisah.

## Tindak lanjut tinjauan kode (commit lanjutan)

- Detail tetap tampil (aksi dinonaktifkan) saat dimuat ulang sesudah perubahan status; fokus pindah ke judul "Tindakan petugas".
- Error aksi dan pemberitahuan berhasil tampil di dalam panel aksi; textarea catatan memakai `aria-invalid` dan `aria-describedby`.
- Jika PATCH berhasil tetapi muat ulang gagal, pesan menyatakan status sudah diperbarui.
- Samaran NIK/KK tetap format `3201********0001` sesuai permintaan; nilai < 12 karakter disamarkan seluruhnya. Tombol tidak lagi memakai `aria-pressed` ganda.
- 404 dari API petugas ditampilkan "Permohonan tidak ditemukan..." (bukan pesan Laravel berbahasa Inggris).
- Daftar: fokus ke ringkasan hasil sesudah filter/paging; halaman di luar jangkauan menampilkan tautan ke halaman 1.
- Pencarian `q` tidak peka huruf besar/kecil memakai `LOWER()` agar sama di SQLite dan PostgreSQL.
- Tipe `StaffApplicationFilters` yang tidak dipakai dihapus.
- Verifikasi: `php artisan test` 94 tes / 931 asersi; lint, tsc, build, `test:demo`, `test-admin-filters` lulus; uji browser 192/192 di 390px dan 1440px, audit database/log 10/10 (database sementara, data fiktif).

## Belum selesai / perlu tindakan

- Saat uji dengan server statis sementara, Next.js meminta file prefetch bertitik (`__next.admin.$d$section.__PAGE__.txt`) sedangkan export menyimpannya sebagai folder bersarang, sehingga muncul 404 tanpa mengganggu navigasi. Perilaku hosting sungguhan perlu dicek.
- Jalankan `php artisan migrate` di setiap environment sebelum membuka detail.
- Sebelum produksi, atur redaksi query string pada access log proxy/web server.
- Ringkasan angka dashboard dan manajemen akun petugas masih M3 berikutnya.
