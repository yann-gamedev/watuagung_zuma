# Progres 18 Oktober 2026 — M2: status pengambilan dan wewenang per peran

Branch: `feat/status-roles`. Tidak ada dependensi baru (Laravel Boost tidak dipasang sesuai persetujuan pengguna).

## Ringkasan

Alur surat kini berjalan sampai warga mengambil surat:

`SUBMITTED → VERIFIED → PROCESSING → WAITING_APPROVAL → APPROVED → READY_FOR_PICKUP → COMPLETED`, plus `NEED_REVISION` dan `REJECTED`.

Wewenang per peran dijaga di server. Hanya `village_head` yang memutuskan `WAITING_APPROVAL`; admin tidak dapat menyetujui. Alur persetujuan masih **[SEMENTARA]** di PRODUCT.md sampai dikonfirmasi pihak desa.

## Backend

- `backend/app/Domain/ApplicationStatus.php` (baru): enum status + satu-satunya tabel transisi per peran (`rules()`, `isTransition`, `canTransition`, `allowedFor`, `requiresNote`, `PANEL_ROLES`).
- `StaffController`:
  - login dan `/staff/me` menerima `staff`, `village_head`, `admin` (tetap satu ability `applications:manage`);
  - `index` memeriksa peran (403), memvalidasi `status` **atau** `statuses[]` (saling eksklusif) dan `page`, paginasi di server, dan setiap item memuat `allowed_transitions`;
  - `update`: transisi di luar alur → 422 `Transisi status tidak valid.`; transisi sah tetapi bukan wewenang → 403 `Peran Anda tidak berwenang melakukan perubahan status ini.`; catatan wajib untuk `REJECTED`/`NEED_REVISION`; status dibaca ulang dengan `lockForUpdate` di dalam transaksi; `application_events.user_id` diisi; respons memuat `allowed_transitions` baru.
- `routes/console.php`: perintah `php artisan staff:create {username} --role= --name= --email=` dengan prompt kata sandi tersembunyi (minimal 12 karakter, diketik dua kali).
- Tes: `tests/Feature/StatusWorkflowTest.php` (baru) — setiap transisi yang diizinkan per peran (data provider), seluruh kombinasi lain ditolak tanpa efek samping (>200 kasus), staff/admin tidak bisa menyetujui, kepala desa tidak bisa melakukan pekerjaan kantor, transisi melompat/dari status akhir, catatan wajib, audit `user_id`, filter `status`/`statuses[]` + paginasi, validasi, tanpa token, peran salah, ability salah, penurunan peran setelah token terbit, klien usang, login/me kepala desa, dan perintah `staff:create`. `ApplicationsApiTest` dan `StaffSessionTest` disesuaikan.
- Dokumentasi: `backend/README.md` (tabel wewenang, cara membuat akun lokal tiga peran), `docs/integrasi.md` (kontrak `allowed_transitions`, `statuses[]`, menu admin).
